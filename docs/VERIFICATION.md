# Release verification

The release keeps executable code, fixed inputs/configuration, saved verification outputs and manuscript reference values directly traceable.

## Reviewer sequence

```bash
python -m compileall -q gppaf scripts examples tests
python -m pytest -q
python scripts/verify_release.py
python scripts/verify_claims.py
python examples/run_all.py --output runs/examples
```

`verify_release.py` checks raw-table hashes, 105 × 10 layerwise completeness, the 105-condition metadata table, row lineage, Eq. (2) identity initialization, environment consistency across the saved folds, the fixed 100-case path file, PA-LCCS certificates and HELS-DP backtracking.

`verify_claims.py` reads the archived, version-labelled five-fold TC-DSFNet artifact set together with the manuscript reference claims. Those five folds were generated by the v1.4.4 implementation and are retained for traceability; they are not described as outputs of the v1.4.5 Eq. (6) implementation. Fresh process/path benchmark directories can be supplied explicitly.

## TC-DSFNet grouped evaluation

```bash
python scripts/cross_validate.py --epochs 100 --candidates 256 --output runs/cross_validation
python scripts/benchmark_process_cv.py --cv-run runs/cross_validation \
  --epochs 100 --candidates 256 --output runs/process_comparison
python scripts/verify_claims.py --process-cv runs/cross_validation \
  --process-comparison runs/process_comparison
```

Grouping precedes augmentation. Every fold stores train/validation/test IDs, augmentation-parent IDs, calibration, trend signs, checkpoint, training history, per-sample evaluation and runtime environment. The archived folds are labelled `artifact_implementation_version = 1.4.4`. In v1.4.5, Eq. (6) averages all retained trend relationships in one global mean; `tests/test_process.py` and the regenerated executable training example verify that corrected implementation. M=256 remains the fixed release evaluation setting; the final English manuscript defines the common Best-of-M evaluation with M as the candidate count.

## PA-HGTS benchmark protocol

```bash
python scripts/benchmark_paths.py --instances /path/to/instances.json \
  --checkpoint PA_HGTS_CHECKPOINT.pt --beam 16 \
  --lambda-cost 1.0 --lambda-bound 0.1 --failure-penalty 1000 \
  --local-cost-weight 1.0 --local-rounds 2 --local-top-edges 8 \
  --aco-ants 6 --aco-iterations 5 --aco-evaporation 0.2 \
  --seed 2026 --output runs/path_benchmark
```

`configs/fig10_release_protocol.json` records the fixed 100-case benchmark defaults. `data/path_validation_100.json` is the packaged benchmark input, and `benchmark_paths.py` accepts the PA-HGTS checkpoint for an evaluation run via `--checkpoint` and exports aligned six-method per-instance and statistical results. The separate compact training-reference run is stored in `reference_results/pa_hgts_training_reference/`.
